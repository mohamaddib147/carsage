- `backend/app/validation.py` — CAR-23 shared server-side limits used by every router: 1-300 char trimmed place text, UUID record ids, bounded finite fuel price, car make/model/year bounds, AI Advisor description/message limits. Mirrors the database CHECK constraints (docs/db_migrations/) and the frontend (src/lib/limits.js) — change them together.

- `backend/app/routers/health.py` — `GET /health`, reports API status and DB reachability without leaking error detail.
- `backend/app/auth.py` — `get_current_user_id` FastAPI dependency: verifies the `Authorization: Bearer <jwt>` header against Supabase Auth, since the backend's service-role client bypasses RLS and so must check the caller's identity itself on any user-scoped endpoint.
- `backend/app/routers/trip_planner.py` — `POST /trip-planner/directions`: origin/destination → distance + durations via Google Maps. `GET /trip-planner/fuel-prices`: current price per fuel type in LBP and USD. `POST /trip-planner/estimate`: the full flow — route + the caller's car's fuel_efficiency (km/L) + fuel price (scraped default or manual override) → estimated cost, saved as a new `trips` row. Requires auth; verifies `car_id` belongs to the caller. All return a clear error message, never a stack trace, on failure. **CAR-42**: the response also includes `estimated_cost_current_traffic_lbp/usd` — the same trip with fuel efficiency reduced via `_traffic_adjusted_efficiency` (a capped, documented heuristic: penalty scales with how much slower the traffic-adjusted duration is than the no-traffic baseline, reaching a 30% max at a 2x slowdown). Only the original light-traffic `estimated_cost_lbp` is persisted to `trips.estimated_cost`, unchanged from before CAR-42 — the traffic-adjusted figure is response-only since it changes on every re-check. `/directions` and `/estimate` responses also carry `route_polyline` (CAR-48, response-only, never persisted). CAR-23: origin/destination are trimmed, 1-300 chars (blank/oversized -> 422 before Google is called); car_id must be a UUID; the fuel price override is positive, <=10,000,000 and never NaN/Infinity.
- `backend/app/routers/car_specs.py` — `GET /cars/spec-suggestions?make=&model=&year=` (CAR-34): best-effort car spec autofill for Car Onboarding. No auth required (public data lookup, not a write); always returns 200 with best-effort/null fields, never errors, so a failed or no-match lookup never blocks onboarding. Response also carries `fuel_tank_capacity_source` (`api_ninjas` | `auto_data` | `ai_estimate` | null). CAR-23: make/model must be non-blank and <=60 chars, year 1900-2100 (else 422 before any lookup).
- `backend/app/routers/ai_advisor.py` — `POST /ai-advisor/classify` (CAR-19, persistence added in CAR-21, YouTube video suggestion added in CAR-40, NHTSA safety grounding added in CAR-36): takes a car issue description + `car_id` (+ optional `conversation_id` to continue a prior conversation), verifies the car and conversation both belong to the caller, saves the user's message, then checks `app.services.nhtsa_safety` — a matching open recall or complaint pattern skips the LLM entirely and forces `mechanic` with an NHTSA-grounded explanation; otherwise classifies via `app.services.llm_client` as before, appending an explicit disclaimer to the guidance if NHTSA doesn't recognize the vehicle at all. Saves the AI's reply (with `recommendation` set), and — only when the recommendation is 'diy' (conserves YouTube quota) — looks up a matching video via `app.services.youtube_client`, updates that same AI message row with it if found, and returns `{conversation_id, recommendation, guidance, video_title, video_url}` (the last two `null` for 'mechanic' or no match). The user's message is saved even if classification then fails. Requires auth. A classification failure returns a clear 503, never a stack trace.
